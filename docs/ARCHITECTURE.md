# Crescendo — Platform Architecture

Crescendo is an intelligent, private-first musical learning, creativity,
practice, recording and performance platform.

The platform is being designed as a long-term musical environment rather
than a single-purpose examination application.

---

## 1. Product Vision

Crescendo brings together:

- Music learning
- Instrument practice
- Musicianship
- Aural training
- Sight-reading
- Music theory
- Composition
- Recording
- Performance
- Intelligent coaching
- Musical progress tracking
- Creative exploration
- Personal musical identity

The first major experience is **Mihira's ABRSM Grade 1 Piano Coach**.

The platform will progressively expand beyond ABRSM into a complete musical
learning and creativity environment.

The long-term objective is to help a learner become:

**Independent → Musical → Expressive → Creative → Confident**

Crescendo is not intended to be merely an examination preparation tool.

It is intended to become a learner's long-term musical environment.

## 3. Intelligent Coach — Pip

Pip is Crescendo's intelligent musical coach.

Pip should behave as a teacher, practice partner, examiner simulator and
musical mentor rather than simply as a chatbot.

### Pip Responsibilities

Pip should be able to:

- Explain musical concepts
- Demonstrate concepts
- Ask questions
- Generate exercises
- Listen to performances
- Analyse practice
- Identify weaknesses
- Recommend practice
- Conduct knowledge tests
- Conduct aural exercises
- Conduct sight-reading exercises
- Conduct mock examinations
- Review progress
- Explain mistakes
- Encourage deliberate practice
- Adapt difficulty
- Schedule revision
- Track mastery

### Example

If the learner asks:

> What is crescendo?

Pip should:

1. Explain the meaning.
2. Show the musical symbol.
3. Demonstrate it on the virtual piano.
4. Show a simple five-note progression.
5. Ask the learner to start softly.
6. Ask the learner to gradually become louder.
7. Record the performance.
8. Analyse the result.
9. Explain what was good.
10. Explain what can be improved.
11. Give another attempt.

The objective is:

**Explain → Demonstrate → Practice → Listen → Evaluate → Improve**

## 4. Learning Architecture

Crescendo follows a deliberate learning cycle.

### Core Learning Loop

**Learn → Example → Exercise → Knowledge Test → Revision → Mock → Fix → Retest**

Every major learning capability should follow this pattern.

### Learn

Introduce the concept in simple language.

### Example

Show or demonstrate the concept.

### Exercise

Allow the learner to practise the concept.

### Knowledge Test

Check whether the learner understands the concept.

### Revision

Return to the concept using spaced repetition.

### Mock

Test the concept in an examination-like environment.

### Fix

Identify the weakness and provide targeted training.

### Retest

Measure whether the weakness has improved.

## 5. Adaptive Learning System

Crescendo should not treat all practice equally.

The system should continuously identify:

- Strong skills
- Weak skills
- Forgotten skills
- Developing skills
- Frequently missed concepts
- Frequently repeated errors
- Skills that have not been practised recently

Practice recommendations should be generated from this information.

### Practice Priority

A conceptual practice priority score may consider:

- Accuracy
- Recency
- Error frequency
- Difficulty
- Confidence
- Time since last revision
- Examination importance
- Historical performance

The objective is to answer:

> What should Mihira practise next?

rather than:

> What can Mihira practise again?

## 8. Sight-Reading Architecture

Sight-reading is treated as a separate intelligent training system.

The system should generate unseen material within the defined Grade 1
curriculum constraints.

### Grade 1 Sight-Reading Constraints

The generator should respect the examination requirements including:

- 2/4
- 3/4
- 4/4
- C major
- G major
- F major
- A minor
- D minor
- Hands separately
- Five-finger positions
- Minims
- Crotchets
- Paired quavers
- Whole-bar rests
- Semibreve rests
- Dotted minims
- Groups of four quavers
- Minim rests
- Crotchet rests
- Legato
- Staccato
- Slurs
- Accents
- Dynamic markings
- Crescendo
- Diminuendo
- Limited accidentals in minor keys

### Sight-Reading Flow

1. Generate unseen exercise.
2. Display the score.
3. Give up to 30 seconds preparation.
4. Allow the learner to scan the music.
5. Start performance.
6. Capture microphone or MIDI input where available.
7. Analyse pitch.
8. Analyse timing.
9. Analyse continuity.
10. Analyse rhythm.
11. Provide coaching feedback.
12. Allow retry.
13. Generate a new unseen exercise.

### Sight-Reading Metrics

Possible coaching metrics:

- Pitch accuracy
- Rhythm accuracy
- Pulse consistency
- Continuity
- Correct notes
- Incorrect notes
- Missed notes
- Stops
- Hesitations
- Tempo stability

The Crescendo sight-reading score is a **coaching diagnostic**.

It is not an official ABRSM mark.

## 9. Aural Training Architecture

Aural training should use musical examples rather than relying only on
abstract metronome beats.

The system should progressively introduce:

- Pulse
- Metre
- 2-beat vs 3-beat recognition
- Echo exercises
- Singing
- Pitch recognition
- Pitch-change recognition
- Dynamics
- Articulation
- Musical character
- Musical features
- Memory

### Aural Exercise Flow

**Listen → Think → Answer → Explain → Retry**

Where possible, exercises should use short piano or musical examples.

The system should provide multiple examples for each concept so that the
learner learns the underlying skill rather than memorising a particular
question.

## 10. Dynamics and Musical Expression

Dynamics should be taught as musical expression rather than as vocabulary
memorisation.

### Dynamic Levels

- pp — very soft
- p — soft
- mp — moderately soft
- mf — moderately loud
- f — loud/strong
- ff — very loud/strong

### Gradual Changes

Crescendo:

- Gradually becoming louder
- Symbol: `<`

Decrescendo / diminuendo:

- Gradually becoming softer
- Symbol: `>`

### Sudden vs Gradual

The learner should understand the difference between:

- Sudden dynamic change
- Gradual dynamic change

Training should include:

- Listening
- Identification
- Demonstration
- Performance
- Recording
- Evaluation

The learner should understand that:

**p → f** is not the same as a crescendo.

## 12. Practice Architecture

Practice should be structured around deliberate practice.

### Practice Session

A session can contain:

1. Warm-up
2. Technical work
3. Piece practice
4. Sight-reading
5. Aural
6. Theory
7. Revision
8. Reflection

### Practice Guidance

Crescendo should encourage:

- Slow practice
- Section practice
- Hands-separate practice where appropriate
- Metronome practice
- Rhythm practice
- Dynamic practice
- Problem isolation
- Repetition with purpose
- Recording
- Self-listening

Core principle:

> Don't practise mistakes. Practise solutions.

Another important principle:

> Keep going.

Especially during sight-reading and mock examinations, the learner should
learn to continue after an error rather than stopping and restarting.

## 15. Engineering Principles

### Accuracy

Musical and examination claims must be validated before being presented
as authoritative.

### Explainability

When Crescendo gives feedback, the learner should understand why.

### Deliberate Practice

The system should target specific weaknesses rather than encourage
unfocused repetition.

### Human-Centred Music

Automation should support musicianship rather than replace musical
judgement.

### Privacy First

Learner data and recordings should be protected by design.

### Modular Architecture

Major capabilities should remain modular so that new instruments,
curricula and learning systems can be added without rebuilding the
platform.

### iPad First

Touch interaction, landscape practice, microphone access, headphones and
future MIDI workflows should be treated as first-class requirements.

### Progressive Enhancement

Core learning should work without requiring advanced hardware or cloud
services.
